================================================================================
                               1. PROJECT OVERVIEW
================================================================================

ReadyMe is a browser extension that helps users find the correct clothing size
by scanning their body and matching measurements to brand size charts.

The backend provides:
  - Body measurement extraction from images using MediaPipe
  - Size prediction with confidence scores
  - Product size chart extraction from e-commerce websites
  - User measurement storage with Supabase
  - JWT authentication for secure profile management

Primary Use Case:
  User uploads a full-body photo -> Backend extracts measurements ->
  Measurements matched against size charts -> User gets size recommendation

================================================================================
                             2. TECHNOLOGY STACK
================================================================================

CORE FRAMEWORK:
  - FastAPI: Modern async Python web framework with automatic OpenAPI docs
  - Python 3.10: Type hints, pattern matching, improved error messages
  - Pydantic 2.9: Data validation and serialization

IMAGE PROCESSING:
  - OpenCV (opencv-python-headless): Image manipulation, color conversion
  - MediaPipe: Google's ML solution for body pose detection
  - Pillow: Image loading and format handling
  - NumPy: Array operations for image data

WEB SCRAPING:
  - BeautifulSoup4: HTML parsing for size chart extraction
  - lxml: Fast XML/HTML parser
  - Requests: HTTP client for fetching product pages

DATABASE & AUTH:
  - Supabase: PostgreSQL database with built-in auth
  - python-jose: JWT token validation

ML (OPTIONAL):
  - TensorFlow/Keras: Neural network for fit prediction
  - Note: API works without TensorFlow, returns defaults

================================================================================
                          4. ENTRY POINT (main.py)
================================================================================

FILE: app/main.py

This is the FastAPI application entry point that:
1. Creates the FastAPI app instance
2. Configures CORS middleware
3. Registers all routers
4. Defines health check endpoints

--------------------------------------------------------------------------------
CODE BREAKDOWN:
--------------------------------------------------------------------------------

APP CREATION:
    app = FastAPI(
        title="ReadyMe Body Measurement API",
        description="API for body measurement scanning and size prediction",
        version="1.0.0"
    )

CORS MIDDLEWARE:
    app.add_middleware(
        CORSMiddleware,
        allow_origins=["*"],           # Allow all origins (dev mode)
        allow_credentials=True,         # Allow cookies
        allow_methods=["*"],            # Allow all HTTP methods
        allow_headers=["*"],            # Allow all headers
    )

    Purpose: Browser extensions need CORS to make cross-origin requests.
    The wildcard "*" allows any extension or web app to call the API.

ROUTER REGISTRATION:
    app.include_router(scan.router, prefix="/scan", tags=["scan"])
    app.include_router(size.router, prefix="/size", tags=["size"])
    app.include_router(product.router, prefix="/product", tags=["product"])
    app.include_router(profile.router, prefix="/profile", tags=["profile"])

    Each router handles a specific domain:
    - /scan/*  -> Body measurement extraction
    - /size/*  -> Size prediction and validation
    - /product/* -> Size chart extraction from URLs
    - /profile/* -> User profile CRUD (requires auth)

ENDPOINTS:
    GET  /              -> Root endpoint, returns API status
    GET  /health        -> Health check for monitoring
    GET  /test-db       -> Test database connection

RUNNING THE SERVER:
    uvicorn app.main:app --reload
    Access docs at: http://localhost:8000/docs

                      5.1 scan.py - Body Measurement Scanning
================================================================================

FILE: app/routers/scan.py

Provides endpoints for analyzing body images and extracting measurements.

--------------------------------------------------------------------------------
ENDPOINTS:
--------------------------------------------------------------------------------

POST /scan/measure
    Description: Analyze uploaded image file and extract body measurements
    Content-Type: multipart/form-data

    Request:
        - image: UploadFile (required) - Image file of full body

    Processing Pipeline:
        1. Read uploaded image file
        2. Convert to PIL Image then numpy array
        3. Preprocess (resize, normalize, denoise)
        4. Extract body landmarks using MediaPipe
        5. Calculate measurements from landmarks

    Response (ScanMeasureResponse):
        {
            "success": true,
            "measurements": {
                "height": 172.5,
                "chest": 96.3,
                "waist": 82.1,
                "hips": 98.4,
                "shoulder_width": 42.7
            }
        }

    Errors:
        - 400: Could not detect body in image
        - 500: Error processing image

--------------------------------------------------------------------------------

POST /scan/measure-base64
    Description: Analyze base64-encoded image and extract measurements
    Content-Type: application/json

    Request Body:
        - image_data: string (required) - Base64 encoded image

    Processing: Same pipeline as /scan/measure

    Response: Same as /scan/measure

    Use Case: Browser extensions often send images as base64 strings

--------------------------------------------------------------------------------
CODE EXPLANATION:
--------------------------------------------------------------------------------

IMAGE LOADING:
    contents = await image.read()
    image_pil = Image.open(io.BytesIO(contents))
    image_array = np.array(image_pil)

    Why: FastAPI's UploadFile needs to be read as bytes, then converted to
    PIL Image for format handling, then to numpy array for OpenCV.

PREPROCESSING:
    preprocessed = preprocess_image(image_array)

    The preprocessing function (in services/preprocessing.py):
    1. Resizes to 640x480 (optimal for MediaPipe)
    2. Normalizes brightness using CLAHE
    3. Denoises using fastNlMeansDenoisingColored

LANDMARK EXTRACTION:
    landmarks = extract_body_landmarks(preprocessed)

    Returns 33 body landmarks with x, y, z coordinates and visibility.
    Returns None if no body detected.

MEASUREMENT CALCULATION:
    measurements = calculate_measurements(landmarks, image_array.shape)

    Converts landmark positions to actual measurements in cm using
    human proportion ratios and pixel-to-cm conversion.

             6.1 mediapipe_extractor.py - Body Landmark Extraction
================================================================================

FILE: app/services/mediapipe_extractor.py

Uses Google's MediaPipe library to detect body pose landmarks.

--------------------------------------------------------------------------------
CLASS: BodyLandmarkExtractor
--------------------------------------------------------------------------------

Initialization:
    self.mp_pose = mp.solutions.pose
    self.pose = self.mp_pose.Pose(
        static_image_mode=True,      # Process single images, not video
        model_complexity=2,          # Highest accuracy model
        enable_segmentation=False,   # Don't segment background
        min_detection_confidence=0.5,
        min_tracking_confidence=0.5
    )

Model Complexity:
    0 = Lite (fastest, least accurate)
    1 = Full (balanced)
    2 = Heavy (slowest, most accurate) <- We use this

--------------------------------------------------------------------------------
METHOD: extract_landmarks(image)
--------------------------------------------------------------------------------

Input: RGB image as numpy array

Output: Dictionary with 33 body landmarks
    {
        'landmarks': [
            {'x': 0.5, 'y': 0.2, 'z': -0.1, 'visibility': 0.99},
            ...  // 33 landmarks total
        ],
        'image_shape': (480, 640, 3)
    }

Returns None if no body detected.

--------------------------------------------------------------------------------
MEDIAPIPE POSE LANDMARKS (33 total)
--------------------------------------------------------------------------------

Index | Landmark          | Use in ReadyMe
------|-------------------|-------------------------
0     | nose              | Height calculation
11    | left_shoulder     | Shoulder width
12    | right_shoulder    | Shoulder width
13    | left_elbow        | (Not used)
14    | right_elbow       | (Not used)
15    | left_wrist        | (Not used)
16    | right_wrist       | (Not used)
23    | left_hip          | Waist, hips
24    | right_hip         | Waist, hips
25    | left_knee         | (Not used)
26    | right_knee        | (Not used)
27    | left_ankle        | Height calculation
28    | right_ankle       | Height calculation

Coordinates are normalized [0, 1] relative to image dimensions.
z provides depth estimation (not used in current implementation).
visibility indicates how visible the landmark is.

--------------------------------------------------------------------------------
GLOBAL INSTANCE PATTERN:
--------------------------------------------------------------------------------

    _extractor = None

    def get_extractor() -> BodyLandmarkExtractor:
        global _extractor
        if _extractor is None:
            _extractor = BodyLandmarkExtractor()
        return _extractor

Purpose: MediaPipe models are expensive to load. Using a singleton prevents
reloading the model on every request.

================================================================================
                 6.2 preprocessing.py - Image Preprocessing
================================================================================

FILE: app/services/preprocessing.py

Prepares images for MediaPipe processing.

--------------------------------------------------------------------------------
FUNCTION: load_image(image_array)
--------------------------------------------------------------------------------

Validates and converts image to RGB format.

    - If grayscale (2D): Convert to RGB
    - If RGBA (4 channels): Remove alpha channel
    - Otherwise: Return as-is

--------------------------------------------------------------------------------
FUNCTION: resize_image(image, target_size=(640, 480))
--------------------------------------------------------------------------------

Resizes image to optimal size for MediaPipe.

Why 640x480?
    - MediaPipe models work best at this resolution
    - Too small: Landmarks become inaccurate
    - Too large: Processing time increases with little benefit

--------------------------------------------------------------------------------
FUNCTION: normalize_image(image)
--------------------------------------------------------------------------------

Normalizes brightness and contrast using CLAHE.

CLAHE (Contrast Limited Adaptive Histogram Equalization):
    - Divides image into 8x8 tiles
    - Applies histogram equalization to each tile
    - Clip limit of 2.0 prevents over-amplification

Process:
    1. Convert RGB to LAB color space
    2. Apply CLAHE to L (lightness) channel
    3. Convert back to RGB

Why LAB color space?
    - Separates lightness from color information
    - Allows brightness adjustment without color distortion

--------------------------------------------------------------------------------
FUNCTION: denoise_image(image)
--------------------------------------------------------------------------------

Removes noise using Non-Local Means algorithm.

    cv2.fastNlMeansDenoisingColored(image, None, 10, 10, 7, 21)

Parameters:
    - h=10: Filter strength for luminance
    - hColor=10: Filter strength for color
    - templateWindowSize=7: Size of template patch
    - searchWindowSize=21: Size of search window

Why needed?
    - Smartphone photos often have noise
    - Noise interferes with landmark detection
    - Non-local means preserves edges better than Gaussian blur

--------------------------------------------------------------------------------
FUNCTION: enhance_contrast(image)
--------------------------------------------------------------------------------

Enhances contrast using histogram equalization on Y channel.

Process:
    1. Convert RGB to YCrCb
    2. Equalize Y (luminance) channel
    3. Convert back to RGB

--------------------------------------------------------------------------------
FUNCTION: preprocess_image(image_array)
--------------------------------------------------------------------------------

Full preprocessing pipeline:

    load_image() -> resize_image() -> normalize_image() -> denoise_image()

Called from scan.py before landmark extraction.

================================================================================
                   6.3 measurement.py - Measurement Calculations
================================================================================

FILE: app/services/measurement.py

Converts MediaPipe landmarks to actual body measurements in centimeters.

--------------------------------------------------------------------------------
HUMAN PROPORTION RATIOS:
--------------------------------------------------------------------------------

    AVERAGE_HUMAN_RATIOS = {
        'height_to_shoulder_ratio': 4.5,   // Height ~4.5x shoulder width
        'chest_to_shoulder_ratio': 1.1,    // Chest ~1.1x shoulder width
        'waist_to_shoulder_ratio': 0.85,   // Waist ~0.85x shoulder width
        'hips_to_shoulder_ratio': 1.05,    // Hips ~1.05x shoulder width
    }

These ratios are based on anthropometric studies and provide reasonable
estimates when absolute scale is unknown.

--------------------------------------------------------------------------------
HELPER FUNCTIONS:
--------------------------------------------------------------------------------

euclidean_distance_3d(p1, p2) -> float
    Calculates 3D distance using x, y, z coordinates

euclidean_distance_2d(p1, p2) -> float
    Calculates 2D distance (ignoring z depth)

--------------------------------------------------------------------------------
MEASUREMENT FUNCTIONS:
--------------------------------------------------------------------------------

calculate_height(landmarks, image_shape) -> float
    Uses nose (0) and average of ankles (27, 28)
    Conversion: height_pixels * 0.5 = cm (approximate)
    Clamped to range [120, 220] cm

    Limitation: Without a reference object, height is estimated.
    Future improvement: Ask user height for calibration.

calculate_shoulder_width(landmarks, image_shape) -> float
    Uses left_shoulder (11) and right_shoulder (12)
    Conversion: distance * image_width * 0.4
    Clamped to range [25, 60] cm

calculate_chest(landmarks, image_shape, shoulder_width) -> float
    Estimated from shoulder width using ratio 1.1
    Clamped to range [70, 140] cm

    Note: MediaPipe doesn't provide depth, so chest is estimated.
    Future improvement: Use user-provided chest measurement.

calculate_waist(landmarks, image_shape, shoulder_width) -> float
    Uses hip landmarks (23, 24) and shoulder ratio
    Clamped to range [50, 130] cm

calculate_hips(landmarks, image_shape, shoulder_width) -> float
    Uses hip landmarks and ratio 1.05
    Clamped to range [60, 150] cm

--------------------------------------------------------------------------------
MAIN FUNCTION: calculate_measurements()
--------------------------------------------------------------------------------

    def calculate_measurements(landmarks_data, image_shape) -> dict:
        landmarks = landmarks_data['landmarks']

        shoulder_width = calculate_shoulder_width(landmarks, image_shape)
        height = calculate_height(landmarks, image_shape)
        chest = calculate_chest(landmarks, image_shape, shoulder_width)
        waist = calculate_waist(landmarks, image_shape, shoulder_width)
        hips = calculate_hips(landmarks, image_shape, shoulder_width)

        return {
            'height': round(height, 1),
            'chest': round(chest, 1),
            'waist': round(waist, 1),
            'hips': round(hips, 1),
            'shoulder_width': round(shoulder_width, 1)
        }

Order matters: Shoulder width is calculated first as it's used for
other measurements.

        "pants":    {"height": 0.15, "waist": 0.4, "hips": 0.35, "chest": 0.0, "shoulder": 0.1},
        "dresses":  {"height": 0.15, "chest": 0.25, "waist": 0.3, "hips": 0.25, "shoulder": 0.05},
        "jackets":  {"height": 0.15, "chest": 0.35, "shoulder": 0.25, "waist": 0.15, "hips": 0.1}
    }

Example interpretation:
    - For shirts: chest is most important (40%), waist second (30%)
    - For pants: waist and hips together account for 75%
    - Jackets prioritize chest and shoulder for proper fit

--------------------------------------------------------------------------------
KEY ALGORITHM: calculate_weighted_distance()
--------------------------------------------------------------------------------

This is the core matching algorithm that determines how well a user's
measurements match a size entry.

Algorithm:
    1. For each measurement (height, chest, waist, hips, shoulder):
        a. Calculate ideal value = (min + max) / 2
        b. Calculate range = max - min
        c. Calculate distance = |user_value - ideal| / range
        d. Weight by category importance
    2. Sum weighted distances
    3. Normalize by total weight

Distance interpretation:
    0.0 = Perfect match (exactly at center of range)
    0.5 = At edge of acceptable range
    1.0+ = Outside the size range

--------------------------------------------------------------------------------
CONFIDENCE SCORE CALCULATION:
--------------------------------------------------------------------------------

    calculate_confidence(distance, measurements_in_range, total_measurements)

Formula:
    base_confidence = 100 - (distance * 100)
    coverage_bonus = (measurements_in_range / total) * 20
    confidence = min(100, base_confidence + coverage_bonus)

Interpretation:
    90-100%: User measurement within exact size range
    70-89%:  User measurement close to size boundary
    50-69%:  Between two sizes (recommend both)
    <50%:    Limited chart data or unusual proportions

--------------------------------------------------------------------------------
FIT TYPE DETERMINATION:
--------------------------------------------------------------------------------

    determine_fit_type(measurements, entry, distance) -> str

Returns:
    - "perfect": distance < 0.3 and most measurements in range
    - "tight": Measurements exceed max bounds (tight on body)
    - "loose": Measurements below min bounds (loose on body)
    - "between_sizes": Close to two different sizes

--------------------------------------------------------------------------------
MAIN FUNCTION: predict_size()
--------------------------------------------------------------------------------

    def predict_size(
        measurements: BodyMeasurements,
        size_chart: Optional[SizeChart] = None,
        use_standard_chart: bool = True,
        category: str = "shirts",
        gender: str = "men"
    ) -> SizePredictionResponse:

Process:
    1. Get size chart (provided or standard)
    2. Sort sizes by min values
    3. Calculate weighted distance for each size
    4. Find best match and alternative
    5. Generate explanation
    6. Check for body proportion warnings

--------------------------------------------------------------------------------
BODY PROPORTION ANALYSIS:
--------------------------------------------------------------------------------

    calculate_body_proportions(measurements) -> dict

Calculates ratios:
    - waist_to_height: Ratio > 0.6 is flagged as unusual
    - chest_to_waist: Ratio > 1.5 is flagged
    - hips_to_waist: For future use

These warnings help users understand when standard sizes might not fit well.

--------------------------------------------------------------------------------
CLASS: TokenData
--------------------------------------------------------------------------------

    class TokenData:
        user_id: str
        email: Optional[str]

Simple dataclass to hold extracted token information.

--------------------------------------------------------------------------------
FUNCTION: decode_supabase_token(token)
--------------------------------------------------------------------------------

Process:
    1. Check JWT_SECRET is configured
    2. Decode token using jose.jwt.decode()
    3. Extract 'sub' claim (user ID)
    4. Extract 'email' claim (optional)

Supabase JWT Claims:
    - sub: User UUID
    - email: User email
    - role: "authenticated" or "anon"
    - aud: "authenticated"
    - iat: Issued at timestamp
    - exp: Expiration timestamp

Errors:
    - JWTError: Token invalid, expired, or malformed
    - Missing sub: Invalid token format

--------------------------------------------------------------------------------
DEPENDENCY: get_current_user
--------------------------------------------------------------------------------

    async def get_current_user(
        credentials: HTTPAuthorizationCredentials = Depends(security)
    ) -> TokenData:

Usage in router:
    from app.auth.jwt_middleware import get_current_user, TokenData

    @router.get("/protected")
    async def protected_route(user: TokenData = Depends(get_current_user)):
        return {"user_id": user.user_id, "email": user.email}

The dependency:
    1. Extracts Authorization header
    2. Validates Bearer token format
    3. Decodes and validates token
    4. Returns TokenData or raises 401

--------------------------------------------------------------------------------
DEPENDENCY: get_current_user_optional
--------------------------------------------------------------------------------

Same as get_current_user but returns None instead of raising 401.
Useful for endpoints that work with or without authentication.
